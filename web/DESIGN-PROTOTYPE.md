# SwarmJet 工作台设计预览

第一版用于讨论任务中心与任务详情的布局、视觉层级和人工介入流程。
使用 `frontend-design` 设计方向，按 `prototype` 工作流制作。此版本是可丢弃的设计研究，不是正式功能实现。

## 启动

```sh
npm run design --prefix web
```

访问 http://localhost:5275/?prototype=workbench#/tasks 。运行常规 Vite 开发服务器时，也可以在该服务器地址加上同样的查询参数。

仅开发环境下启用，生产构建排除原型组件。正式 App 和 API 行为保留。数据均为示例，无网络请求、持久化或真实审批；底部按钮可重置。

## 方向

面向开发者与技术负责人，将需要批准、阻塞、暂停的任务集中呈现。首页用精简概况、待处理区、可筛选的任务列表组织信息。详情先展示当前进展与下一步操作，再分开展示交付结果、执行记录、需求说明；旁栏保留任务信息与活动。

视觉采用深蓝导航、浅灰工作区、白色内容区。对比浅蓝灰侧栏后，用户选择恢复原始深色，保留更鲜明的导航与工作区层次。蓝色表达主要操作与运行中，琥珀色表达等待决策，红色表达阻塞，绿色表达完成。中文优先使用系统无衬线字体，代码和提交版本使用等宽字体。

## 讨论重点

- 是否喜欢这种偏工程工作台的整体气质。
- 待处理区和任务列表的信息密度是否合适。
- 详情页是否能自然回答“做到哪了、为什么停下、我该做什么”。

方向已确认并落地到正式控制台。正式入口为 `/#/tasks`（不带 prototype 查询参数），由 `App.tsx`、`task-presentation.ts` 和 `workbench.css` 实现，使用现有真实 API 与版本绑定审批。任务视图涵盖暂停、依赖、人工合并、部分合并、取消等状态；项目接入、配置与执行器页面复用正式工作台样式。

本预览保留用于设计对照，不作为正式页面的数据源。模拟批准、样例记录与重置按钮仅存在于开发预览。前端构建及浏览器测试覆盖筛选、状态分组、真实命令请求、版本失效错误、窄屏布局及原有接入/终端流程。
