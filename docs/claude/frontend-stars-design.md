# 前端重设计：星图

状态：设计已定稿（2026-10-20），等待对接平台。可运行的设计稿是 [design/stars/index.html](../../design/stars/index.html)：单文件、无构建，数据全部是写死的演示数据。在仓库根目录运行 `python3 -m http.server 4731 --directory design/stars` 即可打开。[design/topology/](../../design/topology/index.html) 是更早的蜂巢版，只作参考，不再沿用。

## 1. 定位

前端不是工作台，也不是控制台。主页就是 swarm 本身：一张活着的星图。用户打开网页，看到的是系统正在运转的样子，而不是一份关于它的报表。

三条原则：

1. 星图永远在最底层，任何操作都不跳页。
2. 信息放在它所属的地方：属于某个对象的，在对象旁边展开；属于项目的，放在项目面板；属于整个平台的，收进平台设置。
3. 隐喻只在图形里，文字永远是大白话。不为了贴合概念去发明名词，别人第一眼就要能看懂。

## 2. 命名：图形用隐喻，文字用大白话

代码、API、数据库里的名字（Hive、Queen、Forager、Cell）这一阶段不改。界面文字统一换成下面的说法（用户已于 2026-10-20 确认）。蜜蜂的叫法在界面上全部去掉，星空的叫法也不写进文字，只体现在图形上。

| 系统里的名字 | 界面文字 | 图形 |
|---|---|---|
| Hive | 项目（一个仓库对应一个项目） | 一个星系 |
| Queen | 主 Agent | 星系中心的恒星 |
| Forager | Agent；有角色时直接写角色名（worker、verifier） | 彗星；verifier 是绕 PR 转的卫星 |
| Cell | 工作环境（界面上很少出现） | 不画 |
| Methodology | 方法论 | 轨道是角色，从外面伸进来的通道是事件规则 |
| PR | PR | 带环的行星 |
| Issue、CI 等外部事件 | Issue、检查结果 | 平台边界外的十字、菱形 |
| Inbox（未认领事件） | 待处理 | 停在边界外、还没被认领的十字 |
| spawn queue | 排队中 | 停在边界上的空心小圈 |
| 用户本人 | 你 | 底部的观测者 ⊙ |

状态的说法：

| 状态 | 文字 | 图形 |
|---|---|---|
| active | 工作中 | 实心彗星头，带彗发和扇形尾巴，背向恒星 |
| parked | 空闲 | 空心头加一截虚线短尾 |
| parked 很久、仍占名额 | 空闲 18 小时，仍占着名额 | 再套一圈虚线 |
| failed | 失败 | × 加断开的尾迹 |
| completed | 已完成 | 尾巴收短、淡出，在轨道上留下一段虚线星轨 |
| Queen 关闭 | 主 Agent 已停用 | 空心圆加斜线 |
| PR 满足合并条件 | 等你决定 | 带环行星外面一圈缓慢转动的强调色虚线 |

设计稿里还用着"星系志""附录""星表""在轨""熄灭"等说法，对接时按上表替换：

- 星系志 → 项目面板（标题就是项目名）
- 附录 → 平台设置
- 星表 → 列表
- 燃料 → 花费
- 向恒星发信 → 对主 Agent 说

## 3. 视觉语言

**基调**：浅色模式是古典铜版星图，深色模式是夜间天文台。整体只用墨色，强调色只有一个，而且只用在和"你"有关的东西上：你发出的消息、等你决定的事。

**颜色 token**

| token | 浅色 | 深色 | 用途 |
|---|---|---|---|
| paper | #E6E5DF 冷调石灰纸 | #0A1020 夜空靛蓝 | 背景 |
| ink | #1B2233 铁胆墨水蓝黑 | #DCE3EF 星光冷白 | 前景、主体 |
| ink2 | ink 58% | ink 56% | 次要文字、中景 |
| ink3 | ink 30% | ink 27% | 注记、背景 |
| hair | ink 12% | ink 9% | 细线、分隔 |
| accent | #94701F 鎏金 | #D7B35E 亮金 | 只用于"你"相关 |

**字体**

- IM Fell English：17 世纪铅字复刻，用于标题、注记、正文。
- Noto Serif SC：中文。
- JetBrains Mono：只用于真实的代码、命令、文件路径。不用等宽字写装饰性的小数据标签。

**层级**分三层墨色浓度：

- 前景：Agent、PR、恒星，用实墨，尺寸最大。
- 中景：轨道、平台边界。
- 背景：星点、经纬网、图框刻度。

每种对象有独有的剪影，不靠颜色区分。

**动效**：只有真实发生的事才动。系统开启"减少动态"时，恒星刻线停转，彗星尾不再闪动。

**禁忌**：

- 渐变、发光、霓虹、科幻 HUD。
- 满屏卡片墙、侧边导航栏。
- 字间距拉开的大写小标签、用中点连接的元信息串、标题里单独强调一个词。
- 多余的说明文字。

## 4. 信息架构

```
星图（底层，三层缩放：全部项目 → 项目 → 单个对象）
├── 对象旁的详情（右侧）：Agent、主 Agent、PR
├── 项目面板（左侧）：方法论、设置、花费、记忆
├── 平台设置（从底部升起）：接入、模型、连接、账簿、账号
├── 时间轴（底部，暂时 mock）
├── 列表（全屏文字视图，可搜索）
└── 对话与命令行（底部一条线）＋ 观测者 ⊙（等你决定的事）
```

**星图三层**

- 全部项目：每个项目一个星系，下方写项目名。有事等你的项目名旁边有一个强调色小点。
- 项目：进入后其他项目退成几乎看不见的远景。PR、Issue 和每个 Agent 旁边都有淡斜体注记。
- 单个对象：镜头推近，右侧展开详情。

**原页面去向**

| 原页面 | 新位置 |
|---|---|
| Hive 列表、Swarm 视图 | 星图本身 |
| Hive 对话 | 点恒星，打开主 Agent 详情（完整对话）；底部那条线是快捷入口 |
| Inbox | 平台边界外未认领的十字；等你决定的事由 ⊙ 提示 |
| 方法论、设置、用量、记忆 | 项目面板 |
| 时间线 | 底部时间轴（暂时 mock） |
| Forager 页（对话、Diff、终端、交接、验证、用量） | 点彗星，在右侧详情里按需折叠 |
| 接入、模型、MCP 连接、用量总账 | 平台设置 |

**同屏规则**：最多两层，即左侧项目面板加右侧详情；平台设置和列表单独出现。永远露出一部分星图。

**操作**

| 操作 | 方式 |
|---|---|
| 缩放 | 滚轮在三层之间切换；空白处拖动平移；双击回到全部项目 |
| 派活 | 把未认领的 Issue 拖到恒星上；或在底部对主 Agent 说 |
| 合并 | 点 ⊙ 或点等你决定的 PR，确认合并 |
| 插话 | 在 Agent 详情底部输入 |
| 跳转 | 底部那条线也是命令行，认得项目名、`PR #8`、`#12` 以及"模型""接入""方法论""列表"等词；输入时下方提示回车会做什么，长句子照常发给主 Agent |

快捷键：`/` 对话，`A` 项目面板，`,` 平台设置，`T` 时间轴，`C` 列表，`G` 经纬线，`D` 深浅色，`Esc` 逐层退出。

**时间轴**：这一阶段只做 mock，但两个目标要提前写清楚，留给后续的可观测性工作：

1. 拖到任意时刻，星图还原那一刻的真实状态。
2. 轴上要有事件刻痕：合并、失败、方法论变更、自动回滚，点击即跳转。

## 5. 数据从哪来

现有 Web API（`internal/api`）已经有：hives、hive 详情与部分更新、queen、foragers（列表、派活）、foragers 取消、hive messages、methodology（当前版本、versions、activate、install）、methodology-templates、`prs/{n}`（只读）、models、模型凭证、tokens、usage、setup、runtime。前端目前靠轮询（`use-resource.ts`）。

对接需要补的后端能力：

| 需要 | 现状 | 用在哪 |
|---|---|---|
| 实时推送（SSE 即可） | 没有，只能轮询 | 消息光脉冲、Agent 状态变化、PR 变化。轮询做不出"活着"的感觉 |
| 某项目的 PR 列表及门禁状态 | 只能按编号查单个 | 星图上的带环行星 |
| 网页端合并 PR | `prs/{n}` 只支持 GET，合并只有 MCP 的 `merge_pr` | ⊙ 和 PR 上的合并 |
| 排队中的请求列表 | 没有 | 平台边界上的空心小圈 |
| 未认领事件列表 | 待确认是否能从 hive messages 过滤得到 | 平台边界外的十字 |
| 方法论事件列表（发布、激活、自动回滚及操作者） | MCP 有版本列表，网页端待确认 | 项目面板的版本历史；以后的时间轴刻痕 |
| 每个 Agent 的花费 | usage 支持按 agent 过滤，待确认粒度 | 详情和列表里的花费 |
| Agent 关联的 Issue | 存在 `issue_number=0` 的问题（见第五轮验收记录） | 彗星和 Issue 之间的关联线 |
| 历史状态重建 | 没有 | 以后的真实时间轴 |

## 6. 还没设计的部分

- **首次使用**：天空几乎是空的，三颗暗星连成一个小星座，分别是"接入 GitHub""填写模型凭证""创建第一个项目"，每完成一步点亮一颗。这里是真实的先后顺序。
- **创建项目**：在全部项目视图的空白处点击，选择仓库，那里点燃一颗恒星，主 Agent 的详情自动打开，开始首次引导对话。
- **登录**：夜空里一条输入线。
- **加载、空状态、错误状态**：API 断开、登录过期、凭证失效。错误要说清楚发生了什么、怎么修，不道歉。
- **手机端**：只保证一件事，就是在手机上回答 ⊙ 的问题、批准合并。

## 7. 实施建议

- **渲染**：先用 Canvas 2D（设计稿就是）。节点超过两三百个、或者帧率不够时，再换 PixiJS。远景层级要降低细节，比如只画点、不画尾巴。
- **字体随前端打包**：自托管部署可能没有外网，不能依赖 Google Fonts。IM Fell English 是 OFL 授权；Noto Serif SC 体积大，按实际用字做子集。
- **无障碍**：列表视图就是键盘和读屏用户的完整入口，所有能在星图上做的事，在列表里都要能做。焦点可见；尊重"减少动态"。
- **迁移方式**：新界面先挂在新路由，逐项对齐现有页面功能，全部对齐后再删除旧页面。Playwright 测试同步改写。
- **主题**：跟随系统，页面上可以手动切换并记住选择。
