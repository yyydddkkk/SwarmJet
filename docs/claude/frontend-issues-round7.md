# 第七轮前端问题清单

排查时间：2026-10-20。对象：本机 sj-r3（dev bb53602），控制台 http://localhost:8180，测试项目 test-for-myself。用真实浏览器、真实数据逐页对照 design/stars/index.html 和 frontend-stars-design.md。

结论：功能链路是通的，但新界面离设计稿差得远。最大的问题有三类：
- 真实数据量一上来就失控：长文本整段展开，历史对象全部上图。
- 动画几乎全部缺失。
- 首屏要等二十多秒。

未覆盖：纸本、夜空主题和简洁风格下的同类问题；手机宽度；300 个 Agent 的真实规模。

## 一、长文本没有折叠（严重）

1. **简报"需要留意"把整段任务提示词原样展开。** 实测一条约 3000 字。右侧状态列被挤成一字一行的竖排（"空闲 / 17 / 小 / 时"）。
2. **列表同样整段展开。** 每个 Agent 还常驻一个"插话"输入框，一屏只能看到三四项。
3. **对象详情里长内容不收起：**
   - Agent 的任务全文和"对话"里的第一条消息内容相同，显示了两遍；
   - PR 的验证结论（数百字）直接铺开；
   - 完整 sha、分支名、Agent 编号在窄列里从中间断行。
4. **星图标签取法不统一。** 有的是角色名加状态（"worker 已取消"），有的是任务原文前几个词（"worker Goal: Add csv_records.py"），中英混杂，没有统一的截断长度。

需要一个统一的文本规则：
- 列表、简报、标签只显示一行摘要。摘要优先取 Issue 或 PR 标题，其次取任务首句，超长用省略号截断。
- 详情里长文默认收起成几行，点"展开"看全文。
- ID 和 sha 默认显示短形式，可一键复制全值。

## 二、星图被历史对象淹没（严重）

5. **已完成、已取消、失败的 Agent 全部画在图上。** 本项目约 40 个；再加上每个 Issue、CI 菱形和已合并 PR 都带全标题，项目层的文字层层叠压，几乎无法阅读。
6. **没有标签避让，也没有按缩放级别显示标签。** 设计稿的做法是：远看只显示形状，靠近或悬停才显示文字。
7. **菱形不在图例里。** 用户不知道它代表什么；菱形的标签又是 PR 或提交的标题全文。
8. **简报"需要留意"会一直堆积旧失败。** 例如第六轮的探针任务、回滚占位任务，没有时间窗，也没有"知道了"可以收起。
9. **简报"需要你"没有按设计折叠。** 设计是最多 3 项加"还有 N 个"，实际 4 项全部列出，数量多时会更长。

建议：
- 默认只显示活跃对象和最近一段时间（例如 24 小时）内结束的对象；
- 更早的对象淡出，或收进"历史"开关；
- 失败项在用户看过、或超过时间窗后降级。

## 三、没有动画（严重）

10. **星图空闲时完全静止。** 实测 3 秒内画布零次重绘。只在有真实消息时出现约 0.8 秒的脉冲，合并或完成时有一次过渡。设计稿里的环境运动全部缺失：
    - 工作中的 Agent 沿轨道缓慢运行；
    - 新 Agent 从恒星飞出（出生动画）；
    - PR 出现时由小变大；
    - verifier 卫星绕 PR 转；
    - 合并时 PR 螺旋落入恒星，随后一圈耀斑；
    - ⊙ 有事等你时外圈呼吸。
11. **CSS 里没有任何 animation 或 transition。** 简报、列表、图例、详情面板、项目面板、平台设置全部是硬切出现和消失。
12. **镜头不会因点击而推进。** 在"全部项目"层点击或双击项目都不会进入项目层（双击被绑定为回到全部项目），只能用左下角的下拉框切换。设计稿是点击星系就推近。

根因有一部分在我写的第七轮规格：我要求"空闲时不持续重绘"，实现方就把环境动画整个去掉了。下一轮要改成：
- 允许低频的环境动画（降帧运行，页面隐藏时停止）；
- 开启"减少动态效果"时全部停止；
- 用帧耗时数据证明开销可接受，而不是一律静止。

## 四、首屏慢、请求多（重要）

13. **首屏约 21 秒。** `GET /api/hives/{id}/prs?state=all` 实测 20954 ms，其他请求都在 50 ms 以内。简报整块显示"正在读取…"，直到最慢的请求返回。前端应该逐区块渲染，不必等全部快照；PR 接口为什么这么慢（逐个查询 GitHub）属于平台问题，需另行归因。
14. **启动时完整快照拉了两次。** 初次加载一次，SSE `ready` 后又一次，两次都包含这条 21 秒的 PR 请求。首次连接时的 `ready` 不需要再拉一次。
15. **每个 Agent 单独请求一次消息。** 本次一共 45 个请求，包括早已结束的历史 Agent。应该只为活跃 Agent 和当前打开的对象拉消息。
16. **加载和登录前的过渡页是无样式文字。** 左上角裸露一行"正在打开项目…"约 10 秒，之后才出现登录页。

## 五、详情与文案（重要）

17. **PR 详情没有标题。** "PR #5"作为标题出现两次，看不到 PR 名称。
18. **"检查结果：还没有检查结果"紧挨着下面的"验证通过"。** 用户分不清 CI 检查和独立验证，应该写明"GitHub CI：无"。
19. **时间戳显示 ISO 原文**，例如 `2026-10-20T02:37:40.89488Z`。应改为本地时间或相对时间。
20. **Agent 详情的标题是角色名"worker"**，应该用任务摘要。已取消的 Agent，小标题仍是"此刻在做什么"。
21. **有开发者口吻的说明**，例如"最近的工具调用：平台暂未提供；下方显示真实消息。"
22. **后端英文原文直接显示**，例如 `no attestation for the current head`、`verifier cancelled by control…`，方法论目录说明也是英文。已知的原因应该转成中文短语。

## 六、布局与样式（次要）

23. **面板盖不住背后的元素。** 打开项目面板后，背后的 Logo 和左下角项目标题会从面板下透出来；列表的遮罩也盖不住左下角标题。
24. **详情面板打开时，底部右侧工具栏被盖住一半。** "确认合并"没有主按钮样式，和普通链接一样。
25. **滚动条是系统默认样式。** 简报、列表、平台设置里粗重的原生滚动条和整体风格不符。
26. **列表搜索框聚焦时是粗金框**，过重。
27. **图例用的是字体字符**（♄、⊙），和画布上实际画出的图形不一致。设计稿的图例是和画布同一套绘制函数画出来的。

## 建议的下一轮组织

只做前端，后端仅在第 13 条归因后另议。建议分四块并行：
- **文本与密度**：第 1～9 条。
  - 统一的摘要和折叠组件；
  - 历史对象的时间窗；
  - 标签避让，并按缩放级别显示标签。
- **动画**：第 10～12 条。
  - 照设计稿补齐环境运动、出生、生长、合并耀斑、⊙ 呼吸；
  - 面板进出过渡；
  - 点击推进镜头；
  - 支持"减少动态效果"，并给出帧耗时数据。
- **数据加载**：第 13～16 条。
  - 逐区块渲染；
  - 首次 `ready` 不重复拉快照；
  - 消息按需拉取；
  - 加载页样式。
- **详情、文案与样式**：第 17～27 条。

验收要用真实部署和真实历史数据，而不是 mock。第七轮的 mock 数据都很短、很干净，所以这些问题在测试里一个都没暴露出来。下一轮的 mock 也要补上长文本和几十个历史对象。
