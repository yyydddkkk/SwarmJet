# Kubernetes 执行模型取代固定 Node 模型

状态：已接受（2026-09-27）

SwarmJet 的开源主线以企业私有部署为目标，Kubernetes 接入将重新设计任务执行归属、工作区、Runner 恢复与资源准入。当前 Docker/远程 Node 模型按主机固定任务，不能靠实现同一 `execution.Node` 接口自然获得 Pod 重调度与恢复语义。公司使用的代码已从 `dev` 的 `ee93919` 建立私有独立快照仓库；企业主线按[接入准备](../kubernetes-migration.md)演进，不承诺长期维护两套完整执行架构，也不把公司旧任务与数据的原地迁移作为 K8s 接入要求。

选择这条路线意味着公司快照不会自动获得企业主线的新功能和修复；公司若有实际维护需求，再单独决定是否移植。企业主线可以移除固定 Node 语义，但 K8s 版本自身仍必须正确处理 Workflow 历史、Pod 重试与升级兼容。创建代码快照不等于迁移公司运行中的部署、数据库或任务。
