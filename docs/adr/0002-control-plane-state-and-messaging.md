# 控制面状态与消息传递的归属

状态：已接受（2026-09-27）

企业主线使用 PostgreSQL 作为 Task、接单唯一性、准入、执行权与人工命令的权威业务状态；Temporal 管理长任务的流程历史；独立消息队列承担 webhook 事件和内部命令的缓冲、投递、重试与消费者扩容。当前不引入 Redis，也不以 Redis 保存权威 Task 状态。消息队列的具体产品和部署拓扑在接入设计时确定。

业务状态变更与待发送命令必须保持同一事务边界；消息队列收到消息或消费者 ACK 不代表业务操作恰好执行一次。数据库中的待发送记录可以缩减为事务性发送意图，由投递器转交消息队列；接收端按稳定事件/命令 ID 去重。此记录不是通用消息队列的替代品。Webhook 可以在消息队列确认持久接收后 ACK，后续接单仍须核对 PostgreSQL 中的唯一性约束与状态。Redis 以后只在可重建缓存等具体需求被验证时重新评估，不作为当前架构的预设依赖。

这一选择接受新增消息队列的运维成本，换取独立扩容、积压管理和消息投递能力，同时保留 PostgreSQL 事务对业务不变量的保护。数万 Issue 突发接入是待压测目标，不是当前已验证容量；现有 inbox 与准入上限均为 1000，不能把当前实现的主动拒绝误判为 PostgreSQL 的性能极限。
