## 已由测试覆盖的关键语义

- Token 加密保存、轮换与不泄露：连接创建后密文不含明文，验证与仓库列表响应不回显 Token。
- 不同主密钥无法解密旧密文；缺失主密钥时连接解析给出可操作错误。
- 受管 Meta-Repo 首次创建幂等、重复初始化不覆盖人工修订。
- 初始化状态机：缺信息提问与回答后续跑、失败重试、取消后重启、固定提交版本、未识别/失败验证标记为未完成。
- 初始化隔离：Agent 请求把只读分析目录与唯一可写生成目录分开；agent 后端拒绝初始化目录之外的生成目录，且不为 `init` 角色授予任务工作区。
- 自动合并开关：新项目默认关闭、nil 保持旧行为、关闭时不进入系统合并且敏感变更不需系统批准、旧历史重放不受影响。
- 地址绑定：保存的连接 Token 只在其验证过的 GitLab 地址上解析；项目地址不一致时保存与解析都被拒绝，仓库与 Meta 地址必须属于配置的 GitLab 主机。
- 初始化执行安全：唯一 owner 租约 + 续租 + 失租保护，等待回答/失败状态不会被轮询自动推进，过期的步骤写入因版本冲突失败，取消会传递到正在执行的操作。
- 验证隔离与门禁：未配置 `INIT_VERIFY_IMAGE` 时验证被阻断；验证失败/缺命令/缺联调配置保持 blocked 且可重试；受管项目启用、建单和 Issue 扫描都要求持久化的 `readyForTasks`。
- 协议一致：`integration.json` 与 `verification.json` 一起读取；就绪判定会检查固定 Meta 提交中的 compose 文件、必需检查与引用的服务。
- 连接换址：未提供并验证新 Token 时拒绝更换连接地址；提供新 Token 后允许并替换密文。
- 验证容器生命周期：容器使用确定性名称并登记，取消、超时或重启后强制删除，不依赖 docker 客户端存活。
- 重试入口：连接阶段失败后从 connect 恢复，而不是带着未固定的仓库版本直接进入分析。
- 分布式兼容：合并 dev 的节点注册、任务固定归属与按节点路由；受管 Meta-Repo 通过 `syncManagedMeta` 传输，受管任务可调度到任意在线节点。
- 并发安装：受管 Meta-Repo 安装使用跨 Manager 有效的项目文件锁，首次安装克隆到临时目录后原子发布，工作区读取持同一把锁，同节点并发安装全部成功。
- 容器清理持久性：只有确认容器已删除或不存在才移除登记；Docker 暂时不可用或超时保留记录以便重试；登记写入失败会阻止容器启动。
- 模型验证：无效模型 400、调用失败 502、超时 504、响应不含提供商密钥。
